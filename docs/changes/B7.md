How the shared pieces are used
- Tables: `DataTable` with a frozen Employee column, `headerGroups` (staff detailed 8/3/3/3, salary sheet Incentive ×2 / Travel ×2) and `maxHeight` on desktop so the header stays sticky and the frozen/scrolling panes stay in sync. Month/year: `MonthYearPicker` (reports/salary years `current-2…+3`, attendance PDF `current-5…+4`, computed per render in IST).
- Exports: every table report exports through `exportTable` (`@/lib/platform/exporter`): real PDF (native `expo-print`, web print-to-PDF), real `.xlsx`, CSV (BOM + RFC-4180), DOC. Employee details uses `exportHtml` with fully escaped HTML. The server attendance PDF uses `downloadAndOpen`.
- History ("View Reports"): `STORAGE_KEYS.generatedReports` scoped by org id, entries `{id, name, uri, filename, mimeType, date, size}` with the REAL mime/extension. Tap a PDF → `openFile`, any other format → `shareFile`; share icon → `shareFile`; delete → confirm, removes the entry AND the file. Missing files are marked "File no longer available" (removable). Capped at **50 entries** (`HISTORY_CAP`); the oldest are evicted together with their files; re-exporting the same file name replaces the older entry that points at the same file. Writers: staff detailed, late, overtime, employee details (PDF and DOC), attendance PDF. Not writers (as in v1): salary sheet, monthly salary, employee shifts.

## Fixes applied (v1 issue → fix)
- Hours worked parsed `total_hours` by splitting on `:` (backend sends decimal hours, fraction dropped) → decimal hours summed then rounded once (`HH:MM` text still understood). `dayHours`/`totalWorkedMinutes` are unit-tested.
- Working-days cache never hit (N duplicate requests) → one request per unique branch+department, cached in the query cache for 10 minutes (`fetchWorkingDays`); failure falls back to calendar days minus Sundays **and shows a warning**.
- Sundays counted with the device time zone → pure calendar math (`reportMonth`).
- Stale rows after a failed reload / month changed mid-load → results are cached per org+period query key; a failure shows an error state with retry, never the previous period's rows.
- Silent failures → partial failures (requests API, per-staff attendance, working days, overtime endpoint, shift lookups, salary breakdown) are surfaced in an inline warning banner; the report still renders with the v1 fallback values.
- Late report: shift times missing from the backend payload printed the punch-in clock time as "Late By" → "—" for Late By and the shift columns, plus an explanatory note; the v1 late rule is otherwise kept (status `late` OR punch-in > shift start + 1 min, minutes = full difference). ISO punch-in timestamps are read in IST. Rows are sorted by the real date, not the `DD-Mon-YYYY` label.
- Overtime: a failed/`success:false` overtime call silently zeroed everything → rows stay, with a visible warning. Export amounts are locale independent (`formatINR`); OT Days exported as `—` when there is no overtime (consistent with hours/amount).
- Exports: HTML-as-PDF/XLS, unescaped CSV without BOM, HTML injection → real PDF/xlsx/CSV/DOC via the exporter; `type:'pdf'` for every history entry → real mime/extension; export disabled while loading or with zero rows; "Preparing Excel…" for every format → "Preparing file…".
- Employee details: auth-null endless spinner (none: the screen relies on the session guard), empty section cards (sections without fields are dropped), file-name sanitising of non-Latin names (exporter keeps Unicode), history only for PDF and before the share (now both formats, after a successful export), inactive staff profile errors → friendly message ("<name> is inactive. Profile details are only available for active staff."), inactive staff get an "Inactive" badge in the directory.
- Employee shifts: unbatched N+1 → batches of 5; shift fetch failure indistinguishable from "no shifts" → error state with retry; staff whose shift record failed are counted in a warning; `StaffRow` no longer defined inside render.
- Attendance PDF: manager name via a direct fetch → session name; status-only success check/error-body-as-report → only a successful download becomes a file and a history entry (the entry is written before the viewer opens, a viewer failure only toasts); stale module-level year list → computed per render; `Generate` guarded against a missing org id.
- Monthly salary: stuck spinner when auth is null → "Session unavailable" state; paid marks and selection were carried over to another month → keyed by period and ignored once month/year changes; stale selection after Pay-one → selection pruned; counts used the non-deduplicated list → rows de-duplicated by user id; paid state derived from `GET /salary/monthly-list` when available, otherwise local (see Backend needs); "₹—" totals replaced by real sums (server list amounts, or the salary breakdown's net salaries when only the staff list is available; `₹—` only when no source exists); confirmation before Pay All / Pay Selected; success dialog dismissable with back/scrim.
- Salary sheet: silent zero-row fallback → still falls back (v1) but with a banner naming the reason (e.g. expired plan 403); local type overrides and the "All Types" pill are reset when month/year changes (the pill label was stale); advance drill-down distinguishes loading / error / empty; direct `fetch` → `salaryReportsApi.listUserAdvances`; export keeps raw numbers + the (possibly overridden) type label.
- Hub: viewer read every file as HTML and shared as `text/html` → real open/share by mime; history never pruned / files never deleted → cap + file deletion; history loading indicator; bottom-nav role hard-coding is no longer relevant (app shell).

## Deferred (v1 behaviour kept; needs a product/backend decision)
- Manager scoping: Late, Overtime, Staff detailed, Monthly salary, Salary sheet, Employee details/shifts call `getAllStaff(orgId)` (org-wide) even when a manager reaches them from `/staff/reports`. The backend narrows a manager's list only when `user_id` is the manager's own id.
- Manager "All Staff" PDF: the picker lists the team but `/api/reports/manager/{id}/monthly-attendance-all/…` merges every active manager/staff of the org (backend). Kept; also the plain single-staff endpoint has no permission check.
- Late definition (no grace period from attendance rules, status `late` OR >1 minute) and "Half Day" column (always 0: backend never emits `half_day`) are unchanged.
- Salary type override on the sheet is local-only and does not recompute net (spec); `salary_type` is `MONTHLY_FIXED` for every row server-side and `fine` is always 0.
- Advance drill-down shows all of the employee's advances, not only the selected month (spec).
- Inactive staff are included in Late/Overtime/Staff detailed/Monthly salary/Shift lists (spec; the backend all-staff list includes them).
- Role label is `Manager` for role 2 and `Employee` otherwise.

## Deviations from spec
- No in-app HTML viewer/WebView for saved reports and employee-profile preview: reports are real files, so History opens PDFs in the OS/browser viewer and shares everything else; the employee "View" button (shown after a PDF export on native) opens the saved PDF. On the web the PDF export goes through the browser print dialog (no file), so it cannot be added to the history or previewed.
- Company logo is not embedded in exported PDFs / header (the exporter has no logo slot); the company name is in the export subtitle `Company | October 2026`. DOC/PDF heading is the report title with the month in the subtitle instead of `Title — Month Year`.
- Month/year selection uses the shared `MonthYearPicker` (stepper + month grid) instead of two dropdowns.
- Overtime table: Branch/Department always muted (as spec); OT badge shown in the frozen cell.
- Delete-confirm copy: "Remove this report from the list and delete its file?" (the file is now deleted too).
- Export sheet for the salary sheet offers PDF, DOC, Excel (no CSV, as the v1 menu).
- Manager "(Me)" entry uses the session name (no extra profile call), employee id = user id.

## Known gaps
- Screens were verified with unit/smoke tests, `tsc`, `eslint` and a web bundle export, not on devices. Visual polish on Android/iOS/dark mode is by construction (tokens only). One interaction to eyeball on web: the salary sheet's Type badge is a pressable inside a pressable table row (row press opens the advance sheet).
- On the web, saved-report `blob:` URLs only live for the page session: after a reload history entries appear as "File no longer available" (removable).
- Saved files containing PII (employee profile PDF/DOC) persist in the app's private saved-files folder until deleted from the history.
