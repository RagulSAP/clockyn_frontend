# F2b2 — API modules: chat, groupChat, announcements, leads, payroll, salaryReports, reports, plans, billing, support, system

## Implemented
`src/api/{chat,groupChat,announcements,leads,payroll,salaryReports,reports,plans,billing,support,system}.ts`, shared helpers `src/api/sharedHelpers.ts` (also used by `params.ts`), DTOs in `src/types/api/<domain>.ts`, barrel lines appended to `src/api/index.ts` (`chatApi` ... `systemApi`), tests in `src/api/__tests__/` (`chatMessaging`, `announcementsLeads`, `payroll`, `salaryReports`, `reportsPlansBilling`, `supportSystem`, `sharedHelpers`; mock helper in `src/api/testUtils/apiMock.ts`).

Ownership decisions: holiday CRUD + weekly offs, attendance rule, version check, feature suggestion and account-deletion request are in `system`; read-only working days is in `salaryReports`; `/company/delete-account` stays in `company` (F2b1); per-staff monthly attendance and staff profile are implemented once in `home` and re-exported from `reports` as `getStaffMonthlyAttendance` / `getEmployeeReportProfile`.

## Fixes applied (v1 issue -> fix)
- Group list/badge sent `organization_id` (and the badge omitted it) -> `org_id` (`listGroups`, `getGroupUnreadTotal`).
- Payslip staff picker read `user_id` that the server never returns -> keyed by `staff_id`; assigned flag now works.
- Assigned payslip lookup was an N+1 loop over templates -> `GET /api/salary/employee/{org}/{staff}` (`getAssignedPayslipId`, `null` when none).
- Lead edit lost the required date -> `requiredDate` is explicit and required on `updateLead`; `leadToInput` round-trips it.
- Dates: advance default date, holiday dates and month params are IST strings (`todayIST`, `monthKey`, `dateParam`); lead creation date derived with `toDateStr`.
- Errors: every `{success:false}` becomes `ApiError` with the server message (overtime report, announcements, advances, assignments ...); plan-block messages survive; no `catch {}` returning defaults (monthly attendance, push token only maps 404 -> null).
- Rates/advance amounts must be positive numbers (`saveWageTemplate`, `createAdvance`); count/turnover details are fetched only for rows lacking them (v1 always N+1).
- Multi-date holiday add reports per-date failures (`addHolidayDates`).

## Deferred (v1 behaviour kept)
- Carry-forward lifecycle and the v1 merge rule (pending/approved only, last row wins => oldest request wins) in `indexCarryForwardByLead`.
- Pricing / GST / renewal maths stays in the billing feature; `createOrder` posts the caller's grand total.
- Announcement targeting rules, plan matrix, late-report definition: untouched.

## Not ported (dead / orphan)
`POST /api/leads/{id}/request` (no backend route), legacy `/announcement/*` helpers (no callers), orphan `/payslip/template*`, `/api/company/details/{org}`, `/face/enroll`; third-party store lookups belong to `@/lib/platform`.
