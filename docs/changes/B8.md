## Implemented
| Screen | Route | Files |

Route files: `src/app/admin/requests/{index,leave,permission,shift-change,device-change}.tsx`, `src/app/admin/expenses/{odometer,travel,bills}.tsx`, `src/app/admin/location.tsx` (thin re-exports). `track_location` is not ported (orphan).

Public surface for other features (Home tile): `import { useRequestBadges } from '@/features/requests/admin'` -> `{ pending, unread, isLoading, refetch, markSeen }` (`pending.total` = Home tile number, `unread[type]` = hub row badges). The hook also keeps the global `badges.requests` counter in sync with `pending.total`.

Data / state: one query `queryKeys.requests.admin(orgId)` (the whole inbox) feeds the hub, the four lists and the badges (a single fetch). Expenses: `queryKeys.expenses.admin/adminOdometer/allowanceRate`. Location: `queryKeys.location.live/history`, `queryKeys.branches.list`. All keys are org scoped.

## Fixes applied (v1 issue -> fix)
- Badge "seen" only worked for leave and was a high-water COUNT that hid new requests -> seen is a per-type SET of request ids (in-memory zustand store scoped by org + user). Opening any of the four lists (and every refresh while it is open) marks its pending requests seen; handling requests never hides new ones; hub badge = pending requests not seen yet. Home keeps `pending.total` (v1). Both come from the same hook. No cross-account leakage (scope key).
- Hub / lists polled even when covered by another screen -> polling (10 s, `usePolling`) runs only while the screen is focused and the app is active.
- Leave: `Promise.all` hid partial failures -> per-date results (`allSettled`), successful dates are patched into the cache, failures surface as an error toast ("Updated 2 of 3 dates. <server message>"); the inbox is refetched either way.
- Leave: request with empty `dates` showed a false success without any call -> decided with ONE `update-status` call (no `leave_date`), real result surfaced.
- `success:false` from `update-status` was ignored silently (all four lists) -> the API layer throws, shown as an error toast; success toast only after success.
- Header pill counted a leave request with `date_statuses = {}` as not pending -> `hasPending` (falls back to the status) everywhere (hub, pill, badges).
- Permission list rendered a blank area when requests had no dates -> empty state.
- `ConfirmModal` re-created on every render, stale `requests` closure for the cache write, per-screen `global.*_cache` -> `useConfirm()` + react-query cache (`setQueryData` patch + invalidate); no globals.
- `current_org_id || ''` -> session `orgId` (`current_org_id || user_id`).
- Load-error toast repeated on every failed poll -> one toast when the refresh starts failing; ErrorState with retry when there is no data.
- Header logo never fetched -> fetched (`authApi.getOrgLogoUrl`) and shown as an avatar.
- Odometer: no confirmation / busy state on approve / reject (double submit) -> confirmation dialog + `useAsyncAction` busy guard + "Processing..." overlay; rejection toast is `info`, not `error`.
- Odometer rate: decimals reached the backend `int` and failed -> input validated (numeric, > 0), rounded to whole rupees with a live hint "Saved as ₹4 per km (whole rupees only)", unit "per km" always shown.
- Odometer: distance with a start reading of 0 km counted as 0 -> `0` is a valid reading (distance = stop - start when stop >= start); server `distance_km` honoured when positive.
- Date filters (odometer / tickets / bills) used the UTC date of the picked value -> plain IST `YYYY-MM-DD` string comparison via `DateField`.
- Expenses: load errors were silent (empty list) -> ErrorState + retry; pull-to-refresh and refetch on focus added (preloaded data was never refreshed); stale-closure `setTickets(tickets.map...)` -> cache patch.
- Staff location: "today" / fetch date used device-local vs UTC dates -> IST (`todayIST`, `isTodayIST`); the fetch date sent is the IST date.
- Plan gate: always said "expired" -> message from `useOrgPlan` (`message('staff_location')`: upgrade hint for a Core plan, expiry text when expired; staff / managers are told to contact their admin and get no Renew button); data fetch is gated behind the plan check; a 403 from the API also shows the locked panel.
- Branch filter did nothing -> filters markers, both counters and every list.
- Stale `selectedStaff` in the interval and route not refreshed -> selection is derived from the live list by id; while today is open the route of the selected staff is refetched with the 10 s poll.
- Freshness is re-evaluated against the poll tick, not only when data changes.
- Dead state removed (`location`, `error`, `slideAnim`, `allStaffPanelFilter`, `loadingRoute`, `orgId` param, `staff_location_stats` key, `showMenuId`, `console.log` noise).

## Deferred (v1 behaviour kept)
- Leave decisions apply to ALL dates of the request (no per-date action UI; spec §7.1). Per-date statuses are displayed read-only as chips when a leave has several dates.
- Permission cards act on exactly one date; shift / device decisions are whole-request; all four allow "Change to ..." after a decision; expense / odometer decisions are final (no change action).
- Odometer amount is `distance x CURRENT org rate` (derived on every render), so a rate edit re-prices every row, including approved ones (spec §7). Default rate 3 is shown until the server returns a rate.
- Freshness threshold 15 min; counters count punched-in staff with coordinates only; "View All Staff" lists everyone returned by the API.
- Home tile metric = `pending.total`, hub rows = unread (v1). They now share one hook; B2 may switch the tile to `unread.total` if product prefers one metric.
- Default map centre (Chennai) until positions or the admin's position are known.
- Seen state is in memory only (lost on restart, like v1) -> after a restart every pending request counts as unread again.

## Backend needs
| Endpoint | Current | Needed | Impact |
|---|---|---|---|
| `GET /requests/admin/{org}` | whole inbox (all types / statuses, no pagination) polled every 10 s per open admin screen | `/requests/admin/{org}/counts` (+ pagination / `status` filter that works for leave) | scale / bandwidth |
| `POST /requests/update-status` (leave, one call per date) | no bulk endpoint, partial failure possible; `Date not found` when the date row is missing; unknown behaviour when called without `leave_date` for a leave with no dates | bulk "all dates" call, defined semantics for date-less leave | atomic leave decisions |
| `POST /expenses/admin/allowance-rate` | `rate: int`; rate is stored only on reading rows, so saving for an org with no readings persists nothing while the API says success; `GET` returns the rate of the latest reading | store the org rate in its own table (accept decimals if product wants paise rates); stamp the rate at approval and expose it | correct persistence, frozen approved amounts |
| `PUT /expenses/admin/{odometer-readings|travel-bill}/{id}/status` | no approver id / role; errors are `{detail}` | accept `action_by` / `role_id` | audit trail |
| `GET /staff-location/locations`, `/history` | latest position selected by the UTC date of the log; `punch_in` / `punch_out` are UTC clock strings; `location_updated_at` may be a naive timestamp | filter by the IST day, return IST times, always send timestamps with an offset (client treats zone-less timestamps as UTC) | correct "today" between 00:00 and 05:30 IST, correct freshness |
| `GET /staff-location/locations` plan gate | 403 for Core / expired | keep (client shows the locked panel on 403) | - |

## Deviations from spec
- Header: title is the screen name and the subtitle the organisation name (v1 had them the other way round for expenses / hub); hub keeps org name as title + "Manage Staff Requests".
- Success popup (2 s) and `Processing...` modal replaced by a toast and the shared `LoadingOverlay`; the three confirmation dialogs use `useConfirm()` with the verbatim titles / messages.
- Expense / odometer decisions get a confirmation dialog (spec §13 asks for it); copy is new ("Approve the ticket of X for ₹1,500.00? This cannot be changed later.").
- Odometer start of 0 km counts (spec listed the falsy-0 quirk as legacy behaviour; treated as a defect).
- Staff location: the Home -> screen AsyncStorage preload (`staff_location_data`) is not ported (query cache instead; Home can `prefetchQuery` with `queryKeys.location.live(orgId, todayIST())`). While a route is open the viewport is fitted to the route and other markers stay visible. Custom zoom buttons are shown on native only (the web map has Leaflet's own control); after a manual zoom the map re-centres on the last programmatic centre. Stat lists / all-staff list are one panel (beside the map on desktop, under it on phones). Map type toggle has Map / Satellite.
- Leave per-date status chips are an addition (read only).

## Known gaps
- `ClockynMap` does not report pan / zoom, so the +/- buttons on native zoom around the last centre.
- No automated E2E; web route bundling verified with `expo export --platform web`, Leaflet map not rendered in jest (mocked).
- The shared `requests` badge is refreshed only while some screen using `useRequestBadges` / the hub is mounted (the realtime socket still increments it on `request_submitted`).
