# B1 — Public / auth screens

Feature folder: `src/features/auth/`. Specs: `00_entry_auth/{index,admin_login,emp_login,client_register}`, `shared/systems/auth_and_session`.

## Implemented
| Route | Route file | Screen |
|---|---|---|
| `/` (welcome, role chooser) | `src/app/index.tsx` (replaced the placeholder) | `WelcomeScreen` — `useRootRedirect` (renders nothing until the session is read, `<Redirect>` to the role home when signed in, else "Get Started" with the Admin Portal / Employee Access cards, feature row, footer; shows the forced / deleted sign-out notice once) |
| `/admin-login` | `src/app/admin-login.tsx` | `AdminLoginScreen` (role 1 only) |
| `/staff-login` | `src/app/staff-login.tsx` | `StaffLoginScreen` (roles 2 / 3 only, device-mismatch flow) |
| `/register` | `src/app/register.tsx` | `RegisterScreen` (company sign-up, single scrolling form grouped in cards; 2-column on desktop) |

Structure: `utils/` (pure: `validation`, `loginMachine`, `registerForm`, `loginService`, `deviceToken`), `hooks/` (`useLoginFlow`, `useContactOtp`, `useRegistration`, `useBackToWelcome`), `components/` (`AuthShell`, `MobileOtpLoginForm`, `PortalCard`, `InfoBox`, `ContactOtpField`, `DynamicStringList`, `LogoPicker`), `screens/`, `__tests__/`.

Login (both portals): mobile (10 digits) -> trusted-device check (`verify-device-token`, only when a token is stored for that number) -> **Continue** (no OTP) or **Get OTP -> Verify & Continue**; `validate-otp` stores the returned device token per mobile (`STORAGE_KEYS.deviceToken`, survives sign-out); `signIn(session)` via `sessionFromLogin` (admin: `orgOverride` = last used company restored through `getLastOrg` + `/company/details`; staff: `deviceToken` in the session); `LoginSuccess` analytics event; push registration (`refreshPushToken`, shared in-flight with the shell bootstrap, never awaited); `last-login-at` written BEFORE `signIn` (5-minute session-check grace; `signIn` also writes it); first-paint queries prefetched (not awaited); `router.goHome(role)`. Admin: an OTP for an unregistered number pushes `/register` with `mobileNumber` + `verifiedContact`. Staff: device mismatch -> "Request Access" (or disabled "Pending...") -> `routes.deviceChangeRequest` with `userId`, `orgId` (+ `mobile`, extra, same as v1); approved device change wipes the stored token. Hardware / on-screen back -> welcome (`replace`).

Registration: logo (`pickImage`, uploaded after the company is created via `authApi.uploadOrgLogo`), company name / address / state / district / pincode / GST, mobile (locked when pre-verified) and e-mail OTP verification (independent, either order, duplicate pre-check via `check-mobile` / `check-email`), branches (>= 1) / departments lists (add focuses the new row, remove when > 1), collapsible "More details" (PAN / website / CIN / TAN / MSME / category with the v1 regexes, non-blocking), `POST /auth/register` payload exactly as v1 (`gst` sent twice by `toRegisterBody`, `device_token` from the stored token for that mobile, integer pincode, defaults `Main Branch` / `General`), `sessionFromRegistration` + `signIn`, `CompleteRegistration` event, attribution `{user_id, source:'organic'}` (fire-and-forget), push registration, prefetch of dashboard / branches / departments / staff, welcome toast "Awesome! Welcome to {org}", open `/admin/home`.

## Fixes applied (v1 -> now)
| v1 issue | Fix |
|---|---|
| Admin screen persisted a staff/manager session before the role check (B1) | Role validated by `sessionFromLogin` BEFORE `signIn`; both portals; nothing is written on a wrong role (tested) |
| `success:false` after OTP verify / Continue left an infinite spinner (B3) | Every run ends in `loginEnded` (`finally`); error toast; after a spent OTP the screen returns to the number step |
| Stale device-mismatch / pending state and Request Access for a previous number (B4) | Reducer clears trusted / mismatch / pending / ids / notice on every number change; stale trust answers are dropped (sequence + number check); Request Access disabled for an invalid number |
| OTP errors always "incorrect" (even network); admin Continue hid `detail` | Server `detail` / network text shown; v1 copy only as fallback |
| `success:false` on Get OTP was silent | `authApi.requestOtp` throws -> error toast |
| Duplicated login code | One `useLoginFlow` + `loginAndBuildSession` |
| Trusted-device check could prompt for notification permission and raced | `registerForPush({prompt:false})` with a 2.5 s timeout; check cancelled on edit |
| Preload awaited before navigating (slow endpoints delayed the home) | Prefetch is fire-and-forget; GlobalCache replaced by `queryClient.prefetchQuery` |
| UTC "today" in the preload | `todayIST()` |
| Registration: address "required" but unchecked; email only needed `@`; pincode unvalidated; mobile accepted non-digits; branch names untrimmed / duplicated; Get OTP enabled during the duplicate check; unencoded e-mail in URL; logo failure silent; OTP codes / tokens logged | Address required (blocking); e-mail format validated; pincode digits-only, 6 digits required; mobile digits only; names trimmed + de-duplicated (case-insensitive); Get OTP waits for the check; `authApi.checkEmailExists` encodes the path; logo failure toasts (registration kept); nothing logged |
| Dead code: add-mode, `email`/`mode` params, location capture, push-permission splash modal, welcome `CustomToast` | Not ported |
| Hidden header / no back affordance on register | Screen header with back (`backOr(adminLogin)`) |
| `/auth/update-push-token` + attribution failures could surface | Swallowed, never block |

## Deferred (v1 behaviour kept)
- No OTP resend / cooldown (a new code needs "Get OTP" again). I added only "Change number" / "Change email" to leave the OTP step (see Deviations).
- Staff Get OTP always sends `role_id: 3`, also for managers.
- Admin single-device enforcement (admins have no device token); device-mismatch blocks the OTP login entirely (only Request Access is offered).
- Client-only enforcement of the OTP-verified flags during registration (the server is the authority).
- Statutory ids (PAN / CIN / TAN / GST) are format hints only and never block registration.
- Company logo URL from the login body is not cached anywhere (the dashboards read it from the company queries).

## Deviations from spec (with reason)
- Welcome copy: product name is Clockyn (the brand/tagline "Attendance Management" kept; cards keep "Admin Portal" / "Employee Access").
- Registration is a grouped single form (not a literal wizard): matches the spec (single scrolling form); sections are cards, two columns on desktop.
- "Add More Details" / "Hide Additional Details" use chevron icons instead of the text glyphs; the animated height is a plain expand.
- "Change number" / "Change email" links on the OTP steps (spec §13 v2 notes): users could not leave a wrong number otherwise. No resend.
- Update-available modals are not repeated on the register screen: the shell (`Bootstrap` / `UpdatePrompt`) owns app-update prompts.
- Registration route params carry only `mobileNumber` + `verifiedContact`; the device token is read from storage (it was stored by the login screen) instead of travelling in the URL.
- A short notice is shown for deleted / inactive accounts and expired / approved device sessions (server message from `verify-device-token`); v1 ignored these flags.
- GST gets the same format hint as PAN/CIN/TAN (`^\d{2}[A-Z]{5}\d{4}[A-Z][1-9A-Z]Z[0-9A-Z]$`, upper-cased while typing); non-blocking.

## Known gaps
- Prefetch keys: `warmHomeQueries` prefetches `queryKeys.home.dashboard(orgId,{date: todayIST()})` (`homeApi.getDashboardStats`), `home.branches(orgId)` (`homeApi.getBranches`) for admins and `attendance.today(userId)` (`attendanceApi.getToday`), `face.registered(userId)` (`faceApi.isFaceRegistered`) for staff, registration also `home.departments` / `home.allStaff`. They are only useful (and only safe) if the dashboard / employee-home screens use the SAME key + the same api function result shape (a mismatching `queryFn` would see foreign data for 10 s). Dashboard builders (B2 / B11) should align or tell B1 to change the keys. `staleTime` of the warm-up is 10 s.
- Permission onboarding after sign-in is the role homes' job (F4), not duplicated here.
- No e2e run against a live backend; web bundle checked with `expo export` (see lead report).
