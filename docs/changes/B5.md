Highlights
- **Settings hub**: data-driven menu (`settings/utils/settingsMenu.ts`): the 8 spec sections in order, one accordion open at a time, nested "Incentive / OT / Bonus" group, "Select Incentive Type" sheet, "Fine / Deduction" -> "Coming soon" toast, Salary Structure gated through `useOrgPlan()` (`salaryGate`), an **Appearance** card (Light / Dark / System via `useThemePreference`), Beyond (Suggest a Feature, Support, More Options, App Permissions, Logout via `useConfirm` + `signOut`, no manual navigation). Desktop (>= 1100) renders two columns. No `preloadedData` params anywhere; target screens read the query cache.
- **More options**: Privacy Policy via the new platform component `WebPage` (iframe on web, WebView on native) from `env.privacyPolicyUrl`, graceful "not configured" state (the deletion button stays available), "Open in browser" fallback. "Request Account Deletion" -> `useConfirm` -> `POST /company/request-deletion/{userId}` -> success toast, session `isActive: 0`, sign-out after 1.5 s (`utils/accountDeletion.ts`); failure keeps the user signed in. The unreachable OTP-gated delete page was not ported.
- **Permissions**: location, camera, notifications, photos with ON/OFF state, summary count + pill, grant buttons (`requestPermission`; Android also asks background location; blocked -> OS settings on native / how-to text in browsers). Re-checked on mount and whenever the app returns to the foreground (`useAppActive`), never polled.
- **Support**: subject picker (subject NAME is sent), message, optional photo (`pickImage`, quality 0.7, remove button), 30 s upload timeout wording, per-ticket reply drafts, status badges (Open / In Progress / Resolved), thread with author labels, resolved tickets tinted + "Reply to reopen this ticket...", photo viewer. **Suggest feature**: limits 120 / 1000 with counter, validation order and copy from the spec.
- **Billing**: pure, unit-tested pricing in `billing/utils/pricing.ts` (staff charge -> minus credit -> coupon (round half up) -> GST 18 % (round half up)), plan state/downgrade matrix in `planState.ts`, quote builder shared by the configurator and the checkout in `quote.ts`, checkout orchestration in `checkoutFlow.ts` (order -> `openCheckout` -> verify), downloaded-invoice registry in `downloads.ts`. iOS is view-only everywhere (`platformPolicy.ts`). Web-portal link only on Android and only when `env.webPortalUrl` is set. Contact links come from `env` and are hidden when empty.

### Route-param contract for other builders (billing)
- `routes.admin.billing.upgrade` params: `mode` = `new` | `upgrade` | `renew` (default `new`) and `planId` (only for `new`: id of the chosen catalogue tier). Everything else is derived from the cached subscription/catalogue.
- `routes.admin.billing.checkout` params: `mode`, `planId`, `staff` (stepper value). Set by the configurator only.
- Home's plan popup ("Renew Plan" / "Upgrade Plan") should push `upgrade` with `{ mode: 'renew' }` (or just `routes.admin.billing.overview`).
- After a verified payment the checkout invalidates `queryKeys.plans.all`, `billing.all`, `staff.count`, `home.all` for the org and patches the session (`planId`, `isFreeTrial: false`). There is no `payment_completed` storage flag any more.

## Fixes applied (v1 -> now)
- Prefetch + JSON `preloadedData` hand-off, silent prefetch failures, stuck "Loading..." overlay, UTC date prefetch -> removed (query cache, typed routes, IST dates).
- Settings plan gate never re-evaluated -> `useOrgPlan()` (cached 5 min, refreshed with the plan queries); still fails open while loading / on error (v1 rule).
- Subscription screen spinner stuck when auth missing, swallowed errors showing a fake "NO PLAN" -> explicit loading / retryable error states; explicit state model (paid-active / paid-expired / trial-active / none) instead of relying on a null subscription (backend returns a placeholder object); the FREE TRIAL badge and "Free trial ends on ..." show for the whole trial (v1 showed ACTIVE until the last day).
- Active-until dates use IST date strings (`todayIST`, inclusive of the end date) instead of `new Date(date) > now`; display dates via `formatDate`; valid-till month arithmetic clamps month ends (31 Jan + 1 month = 28/29 Feb) instead of overflowing.
- Stepper snapped back to the live limit on every focus (lost input) -> initialised once from the subscription.
- Upgrade/Renew for orgs without a paid plan pushed `'undefined'/'null'` params (NaN prices) -> "Select a Plan First" popup / empty state.
- Static "UPGRADING" badge -> mode-specific badge (NEW PLAN / ADD STAFF / RENEWING).
- Coupon: failed attempt no longer removes an applied coupon; the code is URL-encoded by the API client; welcome coupon requests skipped for capacity upgrades and on iOS.
- Payment: verification failure after a successful charge now offers "Retry verification" (no second order, no second charge); every outcome is a dialog/toast (no `Alert`); order-creation errors show the server message; the pay button cannot be double-tapped.
- Invoices: action sheet title said "{number} Plan" -> "Invoice {number}"; the amount (parsed but never shown in v1) is displayed; the downloaded registry drops entries whose file no longer exists; registry is scoped by organisation (`STORAGE_KEYS.downloadedInvoices:orgId`) and is cleared on sign-out by the store; download errors are mapped to the spec copy; files go to the persistent saved-files folder instead of the OS cache.
- Support: tickets refresh on focus / pull-to-refresh (admin replies were invisible until reopening); subject-load failure is hinted instead of silent; the author name comes from the session (no extra `/addstaff` call); empty "My Tickets" section hidden as in the spec.
- Suggest feature: server error text (`detail`) now surfaces; double-submit guarded.
- Permissions: iOS notification permission is read for real (v1 hard-coded `true`); sub-page hardware back (privacy -> menu) handled.
- Duplicate OTP modal / dead state (`showAppPerms`, `permissions`, `downloading`, `showTrialBlock`, `selectedPlan`, `orderData`, unused `PermRow`, inert help icons) not ported.

## Deferred (v1 behaviour kept; needs a product / backend decision)
- All pricing, credit and GST maths stay client-side and are posted as `amount` (the checkout `createOrder` posts the client grand total).
- Credit for a plan change = fixed 10 baseline staff x the CURRENT per-staff price x the current plan's own duration (not pro-rated, not by actual staff).
- Staff-stepper floor: only "buy / change plan over an existing plan" uses the live staff limit as the minimum; capacity upgrade and renewal use 10 (v1 side effect of a missing param, ported as specified). Renewal starts at 10 staff and can lower capacity.
- Renewal is priced as 12 months at the current tier's per-staff price and sends the current tier's `plan_id`.
- Upgrade/Renew while on a free trial are locked (modal on the configurator), buying a plan from Plan Details during a trial is allowed.
- Active-tier / downgrade matrix hard-codes the three plan names (rank map).
- "Used Staff" = every manager/staff user returned by `/home/all-staff` (includes inactive users).
- Single "Fine / Deduction" row is a "Coming soon" placeholder; "Assign Devices" navigates to the existing "coming soon" route.
- Account deletion is a request processed by an operator (not an immediate delete).

## Backend needs
| Endpoint | Current | Needed | Impact |
|---|---|---|---|
| `POST /orders/create` | trusts the client `amount`; credit / renew / top-up context not sent | recompute amount from `plan_id`, `staff_limit`, `coupon_code` and the org's subscription (apply credit + GST server-side) | price tampering; client price is display-only |
| `POST /payments/verify` (renew) | an active plan with the same `plan_id` is treated as a staff top-up: `staff_limit` is increased and `end_date` is NOT extended | explicit renew intent (flag or separate endpoint) that extends `end_date` | UI promises "Valid till +12 months" for renewals |
| `GET /plans/subscription/{org}` | placeholder object (`plan_name` "Free Trial" / null, no `plan_id`, trial flags only inside `data`, `staff_limit` null) | an explicit state field (`paid_active` / `paid_expired` / `trial` / `none`) and trial staff limit | client derives the state heuristically |
| `GET /invoice/history`, `GET /invoice/download` | unauthenticated, keyed by `user_id` / `org_id` / `invoice_number`; 404 `{detail}` for unknown invoice | authenticated access (token or signed URL); stable field names | IDOR risk; `downloadAndOpen` accepts headers once available |
| `POST /company/request-deletion/{userId}`, `POST /company/suggest-feature`, `/support/*` | unauthenticated; ids supplied by the client | authenticated requests, rate limits | abuse / spoofing |
| `POST /support/submit` | photo upload to storage is best-effort: the ticket is created without a photo and still returns `success: true` | report photo failure to the client | silent photo loss |
| `POST /support/{id}/reply` | no size limits; user replies on `resolved` reopen the ticket (works) | optional: return the new status | none |
| Razorpay order response | `amount` treated as rupees by the client (x100 in the platform layer) | confirm unit | wrong charge if the server returns paise |
| Account deletion | request only; store policies expect an in-app deletion path | confirm the operator SLA / copy | review risk |

## Deviations from spec (with reason)
- Settings hub: added the **Appearance** row (requested); **Our Other Applications** dropped (promotes other products); "More Options" and "App Permissions" are real routes (`/admin/more`, `/admin/permissions`) instead of internal views / `?page=` params; the hub's back arrow is gone (tab root).
- More options keeps v1's two views (menu -> privacy page) inside one route with in-screen back handling.
- Permissions: a 4th permission (photos) and explicit grant buttons; the 4-permission summary replaces "x of 3" copy.
- Configurator and checkout take only `mode` / `planId` / `staff` params and re-derive everything from the query cache (v1 passed ~12 stringified values); the configurator also shows the price preview for capacity upgrade and renewal (v1 never rendered it because `currentPlanName` was not passed in those modes).
- Subscription: no separate "refetch on opening Plan Details" spinner (data is already fresh from focus refetch; a background refetch runs); trial popup is shown by the configurator (as v1's effective behaviour) rather than by the unused local popup.
- Invoices: "Delete" is an explicit row in the action sheet (v1: long-press only); the "Downloaded" tab exists on native only (on the web a download is a browser download, nothing to register).
- Copy: vendor names replaced ("Contact sales" link, "Help us build a better Clockyn"); support / sales / privacy / portal links from `@/config/env`, hidden when not configured.
- `Alert.alert` / `window.alert` replaced by `useConfirm` / `useToast`; the mail-to link for discounts is hidden without `env.salesEmail`.

## Known gaps
- Company logo in the settings header (v1 showed it from a module cache) is not shown; the header shows the organisation name only.
- No `prefetchQuery` on press (optional in the brief); target screens fetch on mount.
- Real Razorpay checkout and the native WebView page were not exercised on a device (unit tests inject `openCheckout`).
- `CheckoutHost` (native payment WebView host) is not mounted by the root layout; `CheckoutScreen` mounts it itself. If the shell later mounts it at the root, remove it from the screen (two hosts overwrite each other).
- The legacy single `reply` of a ticket is labelled by the API mapper ("Support"), not "Admin Reply".
- Web: `expo export --platform web` completed successfully with all B5 routes bundled (settings, more, permissions, support, suggest-feature, billing, upgrade, checkout, invoices).
