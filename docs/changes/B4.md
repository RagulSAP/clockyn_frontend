## Fixes applied (v1 issue -> fix)
- Company delete / load had no try/catch (stuck "Deleting Company..." spinner) -> `useAsyncAction` (finally always clears the overlay, server `detail` toasted, session untouched on failure).
- Company view ran details twice per focus, used a different org for logo vs data, stale company count, consumed shared refresh flags -> one `useQuery` per resource keyed by the org shown; flags replaced by query invalidation; logo comes from the same profile as the data.
- After delete: active company switches to the first remaining one **only when the deleted company was the active one** (v1 always switched), session patched via `patchSession`, whole query cache reset, `updated_companies` / `last_org` storage dropped in favour of the store (`setLastOrg` is done by `patchSession`).
- Company edit required a non-blank branch even though the list is hidden in edit mode -> branches only required when adding. Whitespace-only values are trimmed and rejected. Pincode now must be 6 digits (v1 sent `NaN`/null). Picked logo keeps its real mime type (v1 hard-coded PNG); a failed logo upload is reported ("saved, but the logo could not be uploaded") instead of swallowed. Legacy `org_gst` is sent back unchanged in edit (v1 blanked it). Header shows the company being edited, not the active one. OTP: server message shown when the code could not be sent, wrong code clears the digits, new "Change" action to leave the OTP / verified state. No success popup timers (toast + navigate back).
- Manager list: permission-load failure defaulted to all-false and Save then overwrote real permissions -> error state with retry and Save disabled. Permission catalogue now lives on the client and is merged with the server map (empty server map no longer gives "0/0"). Server `detail` shown on remove / save failures. Double load on mount+focus removed. Unused `staffId/staffName/orgId` params not ported.
- Add/edit manager: **department is required** (the backend rejects assignments without a `dept_id`; v1 "none = all" always failed). The form now requires >=1 department, multi-select has "Select all" and "all departments" is sent as every department id explicitly (`buildAssignManagerInput`, one `{branchId, deptId}` per branch x department). Edit pre-fill no longer needs non-empty branch AND department lists; a legacy `deptId = null` assignment pre-selects every department. Conflict check reads a freshly fetched manager list; manager list is fetched once. Success toast added. Filter pickers hidden in edit mode (they only filtered the locked staff field).
- Shifts: empty fields now show messages; >18 h shifts are pre-checked with the backend's explanation (server `detail` is shown for create/update/delete errors too); edit pre-fills the real times; no `cached_shifts` / `shift_need_refresh` flags (stale, not org-scoped) -> query invalidation of `shifts` and `staff.options(shifts)`; delete warns that staff on the shift are unassigned; unassign asks for confirmation and surfaces failures; an assign-sheet load error is an error state (v1 showed "All staff assigned"); id 0 safe (no truthy checks); no timers.
- Attendance rule: loading and saving states, double-tap safe, a failed load is shown (defaults stay) instead of silent, `orgId` guard.
- Holidays: **every response is checked** (parallel writes use `Promise.allSettled`; partial failure says "n of m succeeded", never a success toast on a rejection; off-days `success:false` surfaces); **picked dates clear on month change**; date-only strings handled through `@/lib/datetime` (no `new Date('YYYY-MM-DD')`); holidays grouped by name + branch + department + punch policy (v1 merged different scopes and showed only the first) and ordered by earliest date; duplicate same-name/same-scope dates are skipped with a notice; edit skips PUTs for unchanged records; a failed month load is an error state with retry; month reloads no longer show the previous month's highlights.

## Deferred (v1 behaviour kept; needs a product/backend decision)
- PAN / CIN / TAN format errors are inline hints only and do NOT block saving (as in v1).
- OTP verification is not enforced when ADDING a company (v1); no OTP resend (deferred policy C).
- Holiday scope is stored by branch / department NAME (backend contract); editing a holiday cannot change its scope or cross months.
- Branches cannot be edited from the company edit form (payload `branches: []`); `departments` edit semantics (replace vs append) is server-defined.
- Permission enforcement stays client-side (staff Settings shortcuts); conflict rule between managers is client-side only.
- Managers with "Holiday Management" still have no shortcut in the staff Settings screen (owned by B11).
- Add Company does not switch the active company (v1).

## Deviations from spec
- Row menus (shifts, holidays) open as an action sheet instead of an anchored popover; success popups are toasts; "+ Add New Shift" is the sticky footer button.
- Holiday month/year pickers are the design-system calendar header (previous / next / month-year sheet, years current-1 ... current+4) instead of separate modals; branch/department scope and filter pickers use the shared `Select`.
- Holiday groups use (name, branch, department, policy) as the group key (spec "fix" item 4).
- Pincode 6-digit validation and duplicate-date protection are new rules from the spec's fix lists.
- Shift time displayed as `09:00 AM - 06:00 PM`; times are stored as `HH:mm` and converted to `hh:mmAM/PM` by the API layer.

## Known gaps
- Logo "remove" only clears the local selection (the server has no delete-logo endpoint, as in v1).
- The "Today" outline in the holiday calendar comes from the shared `Calendar` (device-local date, not IST).
- No separate Playwright e2e added.
