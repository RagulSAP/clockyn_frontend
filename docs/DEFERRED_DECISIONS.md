# Deferred decisions register

Every item that an engineer log (`docs/changes/*.md`, "Deferred" and "Needs decision") or a QA matrix (`docs/qa/*.md`, "Needs decision") left open, de-duplicated and grouped by theme. Under `docs/FIX_POLICY.md` section C these items **keep the v1 behaviour** until a product or backend decision is made; nothing here is a defect the engineers forgot.

How to read a row:

- **ID** is stable (`DD-nn`); `backend_changes.md` links to these ids. "Resolved" means this compilation found the answer in the backend snapshot (see `backend_changes.md`, section 0 for the evidence tags) and only a confirmation is left.
- **v1 behaviour kept** says what the app does today (file given when useful).
- **Options** list the realistic choices; the recommended one is marked with a star.
- **Refs** gives the source (log id and section, or QA matrix and row), the v1 spec page (`../project_complete_context/pages/...`, relative to the Clockyn folder, in the v1 specification set) and the test that pins today's behaviour (paths relative to `src/`). "No test" means the behaviour is an absence or a policy.
- Abbreviations for QA files: `Q4a` = `docs/qa/spec-conformance-Q4a.md`, `Q4b-04` / `Q4b-05` / `Q4b-06` = `docs/qa/spec-conformance-Q4b-04.md` / `docs/qa/spec-conformance-Q4b-05.md` / `docs/qa/spec-conformance-Q4b-06.md`, `Q4c` = `docs/qa/spec-conformance-Q4c.md`, `Q4d-A` to `Q4d-D` = `docs/qa/Q4d-A.md` to `Q4d-D.md` (merged in `docs/qa/spec-conformance-Q4d.md`), `Q5` = `docs/qa/cross-cutting-Q5.md`. Change logs: `F2b2`, `F3b`, `F4`, `B1` to `B12` in `docs/changes/`.
