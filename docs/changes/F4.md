## Implemented
- `src/components/overlays/` (barrel `index.ts`): `RateAppModal({visible,onClose})`, `PermissionOnboarding({visible, role:'admin'|'staff', onComplete})`, `usePermissionOnboarding()` -> `{visible, complete}` (+ `isOnboardingDone`, `markOnboardingDone`, `resetOnboarding(userId)`, `onboardingKeyFor`), copy table `permissionCopy.ts`; `useRatePrompt` is re-exported from the barrel.
- `src/lib/rateApp.ts`: pure `evaluateOpen`, `registerAppOpen`, `markRateAppDone`, `snoozeRateApp`, `getRateStoreUrl`, `openRateStore`, `useRatePrompt()` -> `{visible, close}`. Uses `STORAGE_KEYS.rateApp*`.

- `README.md` (setup, env vars, scripts, platforms, dev-client note, folder structure, testing).

## How builders use them
- Home screens (admin and staff): `const rate = useRatePrompt(); const onboarding = usePermissionOnboarding();` then render `<RateAppModal visible={rate.visible} onClose={rate.close} />` and `<PermissionOnboarding visible={onboarding.visible} role="admin" onComplete={onboarding.complete} />` (role `'staff'` for roles 2/3 on the staff home). Call `useRatePrompt()` once per home mount.
- After a fresh registration call `resetOnboarding(userId)` before routing to home if the intro must appear again (v1 `fromRegistration`).
- Show only one of the two at a time if both could be due on the same mount (e.g. `visible={onboarding.visible}` first, rate prompt otherwise); the two are independent.

## Fixes applied (v1 issue -> fix)
- Rate prompt counted every home *focus* (returning from any sub-screen = an "open") -> counted once per mount (strict-mode safe).
- Rate modal: "Rate Us with 0 stars auto-selects 5 stars and needs a second press" quirk removed (CTA disabled until a star is chosen); Esc / Android back / scrim / X all behave as "Maybe later"; the thank-you view's X no longer re-snoozes; store URL from env (no hard-coded ids, no search-page fallback); emoji replaced by icons.
- Permission onboarding: admin used one global completion key -> per-user key for all roles (`@clockyn/permissions-onboarding-done:<userId>`, survives sign-out so a returning user is not asked twice, a second user on the device still is); `step` reset to the intro on every showing; "STEP n OF 4" derived from the step list; `onComplete` fires at most once per showing; notification request goes through `requestPermission('notifications')` (expo on Android, Notification API on web, never throws into the flow); Android back is swallowed on purpose (Skip is always visible).
- Copy ported with the product name replaced by "Clockyn".
