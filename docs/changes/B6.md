Shared pattern, built once:
- `components/TemplateListScreen.tsx` renders header + Add, cards, add / edit dialog and assign dialog from a `TemplateTypeConfig` (`config/types.ts`). The six screens are `<TemplateListScreen config={...} />`.
- Per-type config: `config/wageConfigs.tsx` (daily, hourly), `config/incentiveConfigs.tsx` (overtime, bonus, count, turnover): title / labels / icon / card badges, fields, validation, payload builder, API functions, copy.
- Pure logic in `utils/`: `templates.ts` (numbering, delete-latest rule, duplicates, input filters), `wageForm.ts`, `overtimeForm.ts`, `bonusForm.ts`, `incentiveForms.ts` (count + turnover), `payslipForm.ts` (model, live totals, validation, payload, list order / delete rule), `numberToWords.ts`.
- Reusable UI: `TemplateCard` (⋮ actions, inline delete confirmation, assigned-staff footer), `AssignStaffModal` (ASSIGNED / AVAILABLE lists, bulk assign, Remove, optional "already assigned" confirmation), `PayslipAssignModal`, `PayslipPreviewModal`, `CustomLinesEditor`.

Tests (`src/features/payroll/__tests__`, 113 tests incl. the existing payroll API suite): template numbering / delete rule, payslip live totals / validation / payload / order, amount in words, per-type validators, per-type payload builders (mocked API), smoke + interaction tests for every route screen (render, add / edit validation, payload, delete rule, assign flows, bonus warning, "already assigned" alert, preview).

## Fixes applied (v1 issue -> fix)
- monthly_fixed `parseInt(<uuid>)` sort (meaningless, mutated state in place) -> deterministic order by `createdAt` ascending (the server order), non-mutating; Delete only on the newest template.
- Assigned-staff set was built from a `user_id` the server never returns -> rows keyed by `staff_id`, assigned flag from `is_assigned` plus rows assigned in the session; the staff query is keyed by template + filters, so it is never stale.
- Bare `[]` for an org with no templates left the old list on screen -> the query result always replaces the list; empty state shown.
- Duplicate fetches (mount effect + focus + cached `updated_payslips` handshake, double `loadStaff`) -> one react-query cache per list; saves / assigns invalidate `queryKeys.payroll.all(orgId)`. No AsyncStorage handshake, `router.back()` instead of `router.replace('/monthly_fixed')` (no stacked second list).
- add_payslip `parseInt` live totals (truncated decimals, "NaN") -> integer-paise sum, strict parsing, never NaN; only rows that will be saved (name AND amount) are counted, so totals equal the server's.
- add_payslip accepted text / negative amounts (server 422 -> generic toast) -> inline "Enter a valid amount" + toast; v1 required-field messages / order kept; blank EPF / PT / insurance sent as 0; server error message is now shown.
- Preview had no loading indicator -> skeleton + retry state; `account_number` / `ifsc_code` fall back to `N/A`; negative net pay no longer reads "undefined Rupees Only".
- Silent failures (delete / unassign non-success, list load, edit with failed details fetch, assign list load) -> error toasts with the server detail, retry states in the assign dialog; assign lists are keyed by template (no stale rows from the previous template).
- Dead state / overlays not ported (`loading` never true, overlay tap clearing `saving`, unused logo chain, unused `duration` / `loadingItemId` state, debug `console.log`, unassigned-staff modal, `unassigned-all` call, N+1 bonus assignment lookup, N+1 count / turnover detail enrichment).
- Add-dialog title for daily wages used `list length + 1` -> highest number + 1 for every type (matches the server `max+1`).
- Stale field errors after Cancel / reopening Edit -> errors cleared on every open; SAVE shows "Saving..." and ignores double taps (count / turnover double-submit).
- count_basis whole-number fields silently truncated decimals (`parseInt("12.5")` = 12) -> rejected with "Must be a valid number". Amounts like `12abc` (parsed as 12 in v1) are rejected too.
- count / turnover edit no longer fetches `details/{id}` (could return a per-staff copy row, or fail silently): the template row from the list is used.
- Overtime unreachable "Invalid hours" / overwritten "Duration is required" collapsed to the visible v1 result ("Enter the Duration", trailing space dropped); created templates are no longer fabricated locally with `Date.now()` ids — the list is refetched.
- bonus edit only sent `bonus_percent` so month / year edits were lost -> `updateBonusIncentive` now also sends `month` and `year` (see Shared-code changes).
- bonus "already assigned" check no longer fires one request per bonus: uses `user_ids` from the list (`getBonusAssignedUserIds`, falls back per template only if the server omits them); bonus year picker shows a stored year outside the +/-5 window.
- incentive chooser: real page (v1: modal over a blank page that stayed blank after returning), no pre-fetch (the list endpoints already carry the detail columns), no empty-org race.
- Kebab menu without z-index hacks: inline action row + inline delete confirmation (no overlay stacking). Native alert replaced by in-app dialogs. Toasts replace the v1 success popups (see Deviations).

## Deferred (v1 behaviour kept; needs a product / backend decision)
- Delete-highest-numbered-only is a client-side rule (kept). Server does not enforce it and a delete does not remove assignments / per-user copy rows (daily / hourly), so the next server number skips the deleted one.
- Daily / hourly assignment silently moves staff off their other template of the same type (backend rule). The assign dialog carries a one-line hint (daily_wages §13 asks to surface it) but there is no per-staff "currently on template X" confirmation: the unassigned list does not say which template a staff member is on.
- Overtime allows one staff member on several overtime templates; bonus warns (any bonus, any month / year) but does not prevent it.
- Uniqueness rules (hourly amount, overtime duration, bonus percent, all three count values, turnover amount) are client-side only; the count uniqueness on all three fields is kept as v1 (unusual, confirm intent). Turnover percentage stays uncapped.
- Turnover card keeps v1 copy "Basic Salary: ₹{v}" for the turnover amount (the label is misleading; the redundant second badge is dropped). Product to confirm wording.
- Payslip assignment is one staff at a time with no un-assign (as v1); the staff-detail "Assign" panel params (`staffId`, `staffName`) are not used (route has no such params).
- Plan gate `salary_structure` applies only to the Settings entry (not this feature); `emp_settings` / staff-detail entries have no gate (v1).
- Editing a template changes the pay of already-assigned staff immediately (daily / hourly: per-user copy rows are not updated by the server).

## Deviations from spec (with reason)
- Success popups ("Template Saved!", "Payslip Assigned!", "{k} staff assigned!", ...) are toasts: a second full-screen modal opened right after another modal closes is unreliable on iOS, and toasts already render above modals. Copy unchanged; durations follow the toast defaults (add payslip still waits 1.5 s before returning to the list).
- "Saving..." / "Deleting..." full-screen overlays are shown as the SAVE / Delete button loading state with the same text (no blocking overlay stacked on a modal).
- ⋮ menu and delete confirmation are inline on the card instead of an absolutely positioned dropdown (dropdowns overlapping the next card need z-index hacks and break on web).
- Emoji decorations from the copy tables are replaced by `Icon`s (labels / text unchanged). The "Loading staff..." / "Loading..." modals are skeleton lists.
- Payslip list order: oldest first (server order) with Delete on the newest card; spec R1 leaves the intent open ("newest first" vs effective behaviour) — chose the effective v1 behaviour deterministically.
- Edit dialog for count / turnover opens immediately from the list row (no `details/{id}` call), per §13 "N+1 enrichment is unnecessary".
- Form dialogs are dismissible by scrim / back only for daily wages (as v1); the others require Cancel (v1) — all have an explicit Cancel.
- Amount fields accept decimals up to any length in the input; payslip live totals round to paise.
- A field-level "Enter a valid amount" error (payslip) and the "Must be a valid number" / "Amount must be a valid number" live errors are new where v1 sent NaN; messages reuse existing v1 wording where one existed.

## Known gaps
- Failure toast copy: when the server sends no message the API layer's own fallback is shown (e.g. "Failed to save incentive" instead of the v1 "Failed to save") because `ApiError.detail` carries it; server messages are always preferred.
- Not visually verified on device; layouts use `ResponsiveRow` (1 column phone, 2 columns tablet / desktop) and centred dialogs on wide screens; `expo export --platform web` bundles all routes.
- E2E (Playwright) coverage not added.

## Shared-code changes
- `src/api/payroll.ts`: `updateBonusIncentive(id, bonusPercent, period?)` — additive optional third argument `{ month, year }`; without it the request body is unchanged. Covered by `src/features/payroll/__tests__/bonusApi.test.ts`; the existing `src/api/__tests__/payroll.test.ts` still passes.
