## Fixes applied (v1 issue -> fix)
- Worked time clamped to 0 for sessions crossing midnight -> real length kept (closed sessions and open sessions); a tiny negative open-session value (device clock a few seconds behind the server) counts as 0 instead of 24 h.
- RemainCard and WorkHoursCard disagreed on a `00:00` shift end -> both use `shiftSpanMinutes` (18:00-00:00 = 6 h); a zero-length / invalid shift reads like "no shift" (`--`).
- `isFieldStaff` never read from fresh data -> taken from the freshly fetched staff record; tracking effect waits for the first attendance response (so a resumed tracker is not killed by the "not punched in" default), starts while punched in, stops otherwise; leaving the Home screen no longer stops foreground tracking (v1 stopped it when switching tab).
- `checkPunchLocation` rejection swallowed -> error toast with the server/network message, camera stays closed, button re-enabled.
- Pre-checks in spec order (user -> plan `camera_punch` -> face registered -> permissions -> GPS -> geofence -> camera), implemented as a pure, tested function; the geofence coordinates are reused for the punch (no second GPS fix).
- Face status failing to load no longer sends an enrolled user to registration: it is re-checked first and an error is shown if it still fails.
- Forced (`force_accept`) response was never checked and the UI claimed success whatever the server said -> `success` is verified; if it failed, today's attendance is re-read and success is shown only when the server did record the punch, otherwise the server message is shown. HTTP errors from `/face/punch` (e.g. plan-block 403) show the server message instead of being force-retried.
- Registration capture retried forever (silent stall) -> gives up after 3 attempts per photo with a message; preview shows all four thumbnails; success/failure are in-modal panels (no `Alert`).
- `isDone` could read "COMPLETE" during an open second session -> never done while punched in.
- Request badge: v1 relied on `date_statuses` which the employee endpoint does not return -> uses them when present, request status otherwise, and for leave requests consults the request calendar for per-date statuses.
- Birthday popup re-opened on every focus -> once per day per app run (until dismissed).
- Rate prompt could appear over the punch result -> shown only when no camera/birthday/onboarding popup is open (counted per home mount by F4's hook).
- Calendar: month request failures show an error with retry (v1 turned them into an all-Absent month); day sheet status badge uses the effective status (client half-day reads "Half Day"); half-day rule is midnight-safe; shift before the first approved change uses the shift that preceded it (when the request carries it) instead of the current one; unknown statuses never render white-on-white; dates use IST (`todayIST`), Sunday uses the `statusWeekOff` token.
- Payslip: the preview endpoint takes no month, so the sheet header shows the month/year the response carries (v1 showed the picked month); the N+1 template/staff lookup is replaced by `getAssignedPayslipId`.
- Personal details: Cancel/Back/photo guard unified (discarding with edits asks first); guard has "Keep editing"; only changed fields are validated, with readable labels (v1 blocked saving because of an untouched legacy value and printed internal keys); date and select fields use pickers; no hand-set multipart header; photo upload failure is reported; name change updates the home greeting (`staff` cache + session name); gallery offered besides camera; success timer cleared on unmount; skeleton while loading.
- Settings: Holiday Management / Company Settings rows (no handler in v1) open `/admin/holidays` / `/admin/company`; Profile Settings opens the profile; Logout goes through `signOut` (stops tracking); manager permissions are read reactively from the session.

## Deferred (v1 behaviour kept)
- Face punch `force_accept` fallback: any failure other than "no face" is retried once with `force_accept=true` and shown as "Sent for admin review" (policy decision; makes face matching / branch radius advisory). Only the false-success display was fixed.
- Max 2 sessions/day is enforced on this screen only; server enforcement unverified.
- Delete My Account calls `DELETE /company/delete-account/{userId}` with a single confirm (no typed confirmation); semantics for employees/managers (could it remove the organisation?) need a backend/product answer.
- Sunday is the only weekly off on the calendar; holidays and other weekly offs are not modelled.
- Star-rating cosmetics etc. belong to F4.

## Deviations from spec
- Rate prompt counts one open per home mount (F4's `useRatePrompt`), not one per successful punch (v1 comment said "opens").
- Unsaved-changes guard is a three-button modal (Save / Exit / Keep editing) instead of `useConfirm` (a confirm dialog cannot distinguish "dismissed" from "exit").
- Greeting has no emoji (icon instead); status/button colours use theme tokens instead of the v1 hex values.
- Help & Support and Profile Settings (no handler in v1) are not ported as separate rows: Profile is the General Settings "Profile" row; there is no staff support route.
- Hardware back exit on Home and the "Loading..." prefetch overlay of Personal Details are not ported (shell handles back; the profile screen has its own skeleton and the data is prefetched silently).
- Plan block message uses the staff wording from `useOrgPlan` (same text as v1 for expired plans).

## Known gaps
- Web: `takePictureAsync` resolves a data URI (read as a Blob by the upload client); no OS settings deep link, so permission rows show browser guidance.
- Background tracking is Android-only and no "Always allow" request flow was added (spec mentions it as a v2 improvement; out of scope).
- No on-device pose/liveness detection in face registration (the "tilt" prompts are instructions only, as in v1).
