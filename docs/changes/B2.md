# B2 — Admin dashboard: Home and Overview

## Implemented
| Screen | Route | Files |
|---|---|---|
| Admin home (tab root) | `/admin/home` | `src/app/admin/(tabs)/home.tsx` -> `features/dashboard/screens/HomeScreen.tsx` |
| Overview (status drill-down + staff day detail) | `/admin/overview` (params `date`, `branchId`, `filter`, all optional) | `src/app/admin/overview.tsx` -> `features/dashboard/screens/OverviewScreen.tsx` |

Feature folder `src/features/dashboard/`: `screens/`, `components/` (OrgHeader, FilterBar, SummaryCard, DepartmentCard, QuickActions + ManageGrid, CompanySwitcherSheet, PlanExpiryModal, LogoViewer, DashboardOverlays, `overview/{StatusTiles,StaffAttendanceRow,StaffDayDetail}`), `hooks/` (queries, filters, company switch, plan popup, plan-activated toast, overview data), `utils/` (pure logic: `dashboardLogic`, `planPopup`, `overviewLogic`, colour helpers), tests in `__tests__/` next to each layer (73 tests: logic, plan-popup decision incl. iOS / once per day / per org, date handling, company switch, filters, smoke render + interaction for both screens).

Home: org header (logo -> viewer, name -> `routes.admin.company.view`, switch button -> company switcher sheet), Branch select (ALL + branches, by id), Department switch, Date field (max today, IST), "Staff Overview" card (six figures; each opens `routes.admin.staff.list` with `filter`/`branchId`/`date`; header opens the overview), "No attendance record for this date" rule, department cards (6 badges, tap -> staff list with `deptId`), Quick Actions (Staff Location plan-gated through `useOrgPlan`, Reports, Requests + pending badge), Manage grid (View/Add Staff, Branch, Dept), pull-to-refresh (date back to today) and refresh-on-focus, plan-expiry popup, rate prompt + permission onboarding (`@/components/overlays`, role `admin`), welcome toast for an optional `welcomeMessage` route param. Desktop (>=1100): summary + quick actions left, manage grid right.
Overview: date banner + date field (max today), six status circles with live counts, staff list per bucket (A-Z, de-duplicated, punch-time column rules of the spec), per-person day detail (hero, total hours, one block per session with photos and a full-screen viewer). Phones/tablets switch list <-> detail (header and Android back close the detail first); desktop shows list and detail side by side.

## Fixes applied
| v1 issue | Fix |
|---|---|
| Dates used the UTC date of the device (`toISOString`) on home and local date on overview | One IST business date everywhere (`todayIST`, `YYYY-MM-DD` strings); max selectable = today (IST); pull-to-refresh resets to IST today |
| Company switch kept the previous company's `plan_id` / trial fields and cached data (stale plan gating, stale staff list) | The session is patched with `orgId`, `orgName` AND the new company's plan status + trial end; the previous org's queries are removed; branch/department filters reset (bound to the org id); plan queries are scoped by org so gating refreshes. If branches / stats / plan status of the target fail nothing changes and `Failed to switch company` is shown |
| `filterType` `punch_in` / `punch_out` did not match the staff list's values (fell back to "All Staff") | Params use `punched_in` / `punched_out` (and `late`, `working`, `absent`, `total`) |
| Department cards hard-coded `0` for Late and Punch In | Real counts from `late_punched_in` / `punched_in` of `/home/department-stats` (the mapper already exposes them) |
| Branch identified by name (collisions) | Branch id in state and params; a deleted branch falls back to ALL |
| Overview ignored the branch filter of home | `branchId` is passed home -> overview and applied to counts, status lists and the daily report |
| Overview "Total" ignored the date (all staff ever) | Total = daily attendance report of that date + branch (matches the Total count); same list also provides punch times |
| Overview double staff fetch, `statsData` JSON param, no request de-duplication | Query cache keyed by org/date/branch/bucket; no JSON params |
| `formatHours` could print `HH:60`; `{total_hours && ...}` could render a bare text node | Minute rollover handled; boolean guards |
| Refresh-flag protocol (`*_need_refresh`, `payment_completed`, `updated_companies`) | Query invalidation: the home refetches `home`, `requests.pendingCounts`, `company`, `plans` scopes on focus and on pull-to-refresh; a plan that turns into an active paid plan toasts `Plan activated! Dashboard refreshed.` |
| Org name sync + logo refresh via flags / event emitter | `companyApi.getCompanyDetails` name is synced into the session; logo is a query (company edit invalidates `queryKeys.company.all`) |
| Plan popup key was global per device and written on iOS where nothing is shown | Key is per day AND per organisation, written only when the popup is actually shown; iOS never queries / shows it |
| Staff Location gate fail-open + a stuck loader when no auth data | Uses `useOrgPlan` (fails open only while the status is unknown); no blocking loader (the location screen loads its own data) |
| Missing `user_id` route param left poll / push / permissions / switcher inert | Everything derives from the session |
| Silent failures | Failed loads toast the server message (`Failed to load dashboard data`, `Department data not available`, `Failed to load companies`, `Failed to load staff`, ...) and show inline retry states |
| Rate prompt counted every focus | Handled by `useRatePrompt` (one count per mount) |
| `AsyncStorage.clear()` on forced logout, hardware-back exit, `home_rendered` flag, notification panel state | Not ported (dead / replaced by the shell) |

## Deferred (v1 behaviour kept; needs a decision)
- Admin single-device 5 s session poll: inert in v1 (admins have no device token) — not ported. Real admin single-device enforcement is a product decision.
- Forced logout on a deleted / invalid organisation (404 on stats): unreachable in v1; not implemented (an error toast + retry is shown). Decide the intended behaviour (likely: 404 -> sign out).
- Plan-expiry boundary: end dates are treated as valid through the end day (IST); v1 compared UTC-midnight instants. Window (7 days), once per day, expired = non-dismissible kept.
- Plan gate matrix, "Late" definition, `working` == `punched_in` list (server returns the same list), "no attendance record" rule (past dates only, absent ignored): unchanged.
- Push-token registration (v1 F21) and the app-update soft/force modals are owned by the shell bootstrap (F3b) and are not repeated on home.
- Punch-notification panel (dead UI): not built. `STORAGE_KEYS.punchNotifications` is still unused here.
- `fromRegistration` forced permission onboarding: the registration flow can call `resetOnboarding(userId)` from `@/components/overlays` before navigating; home only supports the optional `welcomeMessage` param.

## Backend needs
| Endpoint | Current behaviour | Needed change | Impact |
|---|---|---|---|
| `GET /home/department-stats` | Not manager-scoped (a manager's own id yields empty) | None for the admin home (admin only); apply `get_manager_scope` if managers ever get the dashboard | — |
| `GET /home/dashboard-status`, `/home/*-staff` | `working` and `punched_in` return the same data; `late` only for staff with a shift | Product decision on distinct "working" semantics | Two figures always equal |

| Pending requests | No counts endpoint; computed client-side from `/requests/admin/{org}` | Counts endpoint | Perf only |

## Deviations from spec
- The whole Staff Overview card is not one tap target: figures open the staff list (per the assignment / all_Staff contract), the card header ("Overview >") opens the Overview. When there is no attendance record neither is tappable.
- Department mode shows no duplicate "No attendance record" text under the card (the card already shows it).
- Overview "Total" bucket is date and branch aware (see Fixes).
- Overview date banner is a static gradient card plus a labelled date field (instead of one tappable banner with a "Change Date" badge); the logo in the header is dropped (the standard screen header shows the company name).
- Plan popup renewals pass only `mode: 'renew'` to `routes.admin.billing.upgrade` (B5 derives plan, staff, start date from its cache); the trial popup opens `routes.admin.billing.overview`.
- Staff Location navigates to `routes.admin.location` with a `date` param (v1 pre-loaded the data into storage); the location screen currently ignores it.
- Overview extra params `branchId` and `filter` are additions to `routes.admin.overview` (`date`); `routes.ts` comment was not edited.

## Known gaps
- No unit test drives the "no attendance record" state through the UI (the date field is a native picker); the rule itself is covered by `dashboardLogic.test.ts`.
- Rate prompt / permission onboarding are mocked in the smoke test (their own tests live with `@/components/overlays`).
- Company switch warms branches / stats for the CURRENT date only; the selected date's stats of the new org load on first render.
- Visual QA on device / browser was not performed (tests + `expo export --platform web` only).

## Shared-code changes
None. (Dashboard-specific queries use `queryKeys.home.list(orgId, { kind: ... })` so `queryKeys.ts` is untouched.) `expo export --platform web` bundles both routes.
